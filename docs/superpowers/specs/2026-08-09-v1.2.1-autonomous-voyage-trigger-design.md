# v1.2.1 Autonomous Voyage Trigger

## Goal

Make Commodore autonomy useful without allowing autonomy instructions to bypass
Armada workflow. Net-new implementation spanning multiple files must enter
voyage flow. “Do it on your own” removes routine questions, but does not
convert voyage work into in-window work or replace contract approval.

## Behavior

### Execution-mode precedence

Commodore evaluates explicit user mode instructions first, then contract state,
then scope and risk policy, then autonomy preference.

- An explicit request to run in-window is honored, subject to existing write
  delegation and safety boundaries.
- An approved contract authorizes implementation and automatic voyage launch.
- Net-new multi-file implementation is voyage work by default, regardless of
  project size or low-risk classification.
- Low risk changes use lighter staffing and evidence inside a voyage; low risk
  does not downgrade multi-file implementation to in-window work.
- “Do it on your own” means infer routine implementation, staffing, test, and
  phase decisions without asking for details.
- “Do it on your own” does not authorize implementation before approval or
  bypass required safety and contract gates.

### Approval and launch

For clear net-new multi-file implementation:

1. Commodore inspects repository and request.
2. Commodore drafts or updates contract, phases, criteria, and assumptions.
3. Commodore asks for contract approval only when approval is unresolved.
4. After approval, Commodore launches existing voyage flow automatically.
5. Commodore does not ask a second “should I run voyage?” question.
6. Voyage Commodore owns implementation, dispatch, gates, QA, evidence, and
   PR inside sandbox.

For small single-file work, questions, reviews, investigations, and ledger
maintenance, in-window mode remains valid.

## Implementation Surface

  rules.
- Keep existing voyage commands and approval gate unchanged unless tests expose
  a launch defect.
- Add prompt regression tests covering multi-file scope, low-risk precedence,
  autonomy language, approval-only confirmation, and no main-checkout
  implementation.
- Add or update generated-artifact expectations if prompt snapshots change.
- Bump `package.json`, `package-lock.json`, and CLI version to `1.2.1`.
- Add a `1.2.1` changelog entry describing autonomous voyage selection.

## Error Handling

- Missing approval blocks launch and requests approval; it does not start
  implementation.
- Ambiguous product decisions may still prompt once.
- Explicit in-window override does not grant main Commodore source-edit rights;
  existing worker delegation and permission boundaries remain active.
- If voyage launch fails, report the concrete command/error and do not claim
  implementation started.
